# P2 边界层（下篇）实现计划：Policy Engine、Effect Journal 与驱动

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 Policy Engine 与 Effect Journal，并把 P2 上篇建好但没有生产调用方的十一个 pub 项经驱动接上运行时。

**Architecture:** 新增 `continuum-effect`（Effect Journal）与 `continuum-policy`（策略裁决）两个 crate；驱动放在既有的 `continuum-runtime`，它运行调用方给定的命令、在沙箱里执行、经 Integration Gate 集成、把声明的外部操作按「命令即效应」记入 Journal。

**Tech Stack:** Rust 1.95.0 / edition 2024；`continuum-persist`（SQLite 事务与迁移）；`continuum-events`（审计）；`serde_json`（策略条件的受限表示）；上篇的 `continuum-workspace` 与 `continuum-sandbox`。

**设计依据：** `docs/superpowers/specs/2026-10-03-p2b-driver-design.md`。

## Global Constraints

- 工具链固定 rustc 1.95.0 / cargo 1.95.0，edition 2024。
- **依赖方向禁止反向。** 本计划新增的边：
  `continuum-effect → continuum-core, continuum-persist, continuum-events`；
  `continuum-policy → continuum-core, continuum-persist, continuum-artifact, continuum-effect`；
  `continuum-runtime → 两者`。
  `crates/continuum-runtime/tests/dependency_direction.rs` 的 `ALL_CRATES` 从 workspace 成员派生，
  `ALLOWED` 的比对是**双向**的（声明了就必须真实存在，反之亦然）；**新增 crate 后该测试立即失败**，
  须在 `ALLOWED` 登记后才能通过。注意 `continuum-runtime` 的条目历来记的是**规范允许集合**
  （含尚未使用的），与叶子 crate 的条目语义不同——见 `docs/superpowers/p2-followups.md` 第三节。
- `continuum-core` 不含 I/O。
- 数据库连接对象在 `continuum-persist` 内私有，外部 crate 只能通过 `Tx` 访问。
- **枚举列的落库编码一律小写、多词以 `_` 连接，经显式辅助函数读写，不依赖 serde。** 每张表的读写函数与表定义放在同一 crate。`continuum-runtime` 不直接对这些列写 SQL 字面量。
- 迁移编号**须先查已占用的值**（P1 用 10、20；上篇用 30），取未占用的。
- 代码注释、错误信息、测试断言信息用中文。标识符用英文。
- `cargo test --workspace --no-fail-fast` 必须全绿，**0 warning**。
- **不修改用户目录的权限位。** 不在仓库中写入任何凭据。
- **不要用 `git add -A`，不要 `git commit --amend`。** 执行期间工作区由实现者与协调者共用，只 `git add <显式路径>`。

## 关于本计划的代码块

本项目的既有事实：手写的计划代码块错误率很高（P1 出过 20+ 处事实错误），且已确立
「**代码块是示意，正文的措辞才是约束**」。因此本计划中：类型定义、SQL、函数签名、测试断言
给出完整代码；直白的过程代码以正文描述；凡与既有 crate 交互的签名，实现前须先读该 crate
的源码确认，不符时以源码为准并回报。

## 三条已付过代价的纪律

1. **变异必须跑全量 `--no-fail-fast`** 下**否定结论**（「不变红」）。正向的「变红」结论跑全量是加分。
   本项目出过一次「单跑一条用例时不变红、全套跑却变红」的误判。
2. **凡注释写绝对措辞，必须有对应用例**；写不出的就改成名副其实的说法。本项目的 crate 已因
   「注释与实际不符」吃过多次亏。
3. **失败路径的测试，断言「返回了 Err」通常不够，要断言是哪一种 Err。**

```rust
#[test]
fn the_documented_transitions_are_accepted() {

    let legal = [

        (Planned, Failed),
        (Planned, RolledBack),
        (Authorized, Executing),
        (Authorized, Failed),
        (Authorized, RolledBack),
        (Executing, Committed),
        (Executing, Failed),
        (Executing, Unknown),
        (Unknown, Committed),
        (Unknown, Failed),
        (Unknown, RolledBack),
        (Unknown, Unknown),
    ];

        assert_eq!(transition(from, to).unwrap(), to, "{from:?} → {to:?} 应被接受");
    }
}

fn a_transition_outside_the_table_is_rejected() {

fn the_three_terminal_states_have_no_outgoing_edges() {

        for to in EffectState::ALL {
            assert!(
```

```rust
/// 设计 §7.5 的六个效应类型。封闭枚举：策略要按类型裁决，开放类型会让策略表漏判。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum EffectType { SendEmail, PushBranch, Publish, DeleteRemote, Charge, Deploy }

/// 设计 §7.2 的七个状态。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum EffectState { Planned, Authorized, Executing, Committed, Failed, RolledBack, Unknown }

impl EffectState {
    /// 全部变体，供全量遍历的用例使用（与 P1 的 `NodeState::ALL` 同形）。
    pub const ALL: [EffectState; 7] = [ /* 七个变体 */ ];
}

#[derive(Debug, Clone, PartialEq, Eq, thiserror::Error)]
pub enum StateError {
    #[error("迁移 {from:?} → {to:?} 不在允许的迁移表内")]
    Illegal { from: EffectState, to: EffectState },
}

/// 设计 §7.2 的迁移表。表外一律拒绝。
pub fn transition(from: EffectState, to: EffectState) -> Result<EffectState, StateError>;

/// 设计 §7.1 的记录体。字段与类型照该节。
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Effect {
    pub id: EffectId,
    pub effect_type: EffectType,
    pub target: String,
    pub parameters: serde_json::Value,
    pub authorization: String,
    pub idempotency_key: String,
    pub state: EffectState,
    pub planned_at: i64,
    pub updated_at: i64,
}
```

`EffectId` 为字符串新类型，形态与 P1 的 `ArtifactId` 一致（`new` / `as_str` / `Display` + serde 派生）。

**落库编码的辅助函数**（`effect_type_str`/`parse_effect_type`、`state_str`/`parse_state`）放
`persist.rs`，与表定义同址——本 task 只定义类型，**不落库**，辅助函数在 Task 2 写。

```rust
/// 设计 §5.2 的六级。数字即顺序，越大越弱。
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum Level { SystemSafety = 1, ExplicitCurrent = 2, UserPersistent = 3, Project = 4, RuntimeDefault = 5, ModelSuggestion = 6 }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Decision { Allow, Deny, RequireApproval }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Scope { User, Project }

#[derive(Debug, Clone, PartialEq)]
pub struct Policy {
    pub level: Level,
    pub condition: Condition,
    pub decision: Decision,
    pub scope: Scope,
}

/// 受限的 JSON 谓词：事实名 / 比较 / 取值的合取。
#[derive(Debug, Clone, PartialEq)]
pub struct Condition(/* 私有：析取列表，每项是 (FactName, Op, Value) 的合取 */);

impl Condition {
    /// 解析。任何一项不符即返回 `Err`——**不是**「不匹配」。
    pub fn parse(value: &serde_json::Value) -> Result<Self, PolicyError>;
    /// 求值。所引用的事实不在上下文中即该项不成立。
    pub fn matches(&self, ctx: &PolicyContext) -> bool;
}
```
