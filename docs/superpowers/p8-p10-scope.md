# P8–P10 范围与判据

日期：2026-10-18
状态：范围提案（已由协调者确认切法）；**本文只写范围与判据，不写设计**。
依据：`docs/02-工程.md`（层与缺口）、`docs/spec/05-normative.md`、`docs/spec/02-positioning.md`、`docs/spec/03-product-drive.md`、`docs/superpowers/p5-followups.md`、`docs/superpowers/p6-followups.md`、`docs/ui-contract/`。

## 零、口径

- **P0–P7 是「层」的批次**：P5 即工程文档第 8 层（跨领域工程），P6 即第 6 层（认知工程），P7 即第 7 层（长期循环工程）。层已到此为止。
- **P8–P10 是「跨层批次」**：它们不再增加新层，处理的是「层已声明、但实现体/规范裁定缺失」的部分。
- **P9 与 P10 同职责**：都是规范收口（规范修订 + 对应实现，或具名的「不关闭」理由）；只是主题不同。
- **产品化不占批次**：作为横切义务与交付清单（见第四节）。
- 每批仍走既有流程：**设计 → 计划 → SDD 执行 → 终审 → 合入 main**；涉及规范条款的收口必须有规范维护者参与，产出写回规范或登记为不关闭。

## 一、P8：执行体与端到端

**目标**：把「接口/声明已冻结、实现体为空」的部件补成可运行链路——让系统第一次能对真实 Intent 跑完「模型调用 → 工具执行 → 产物落库 → 验证」。

### 1.1 范围

| 项 | 内容 | 依据 |
|---|---|---|
| 节点执行器 | §279 的端到端落点：节点执行前必经 Context Compiler；P6A 的 `ContextPackage` 第一次被真实消费 | §279 |
| Provider Adapter ×4 | OpenAI / Anthropic / 本地 / 自定义，落 `impl ModelProvider` | §315 §80 |
| Tool Adapter / Connector | `impl ToolProvider`、具体 Connector | §316 §124 |
| 领域算子实现体 | 按需求优先级落 `OperatorImpl`（至少代码与图像先，研究/媒体随后） | §16 §186 §330 §328 §329 §323–§327 |
| 执行层未决两项 | **ENG-002**（非确定节点增量重算）、**ENG-003**（Artifact 身份主从）——在 P8 设计阶段裁定 | §10.1 |
| 可推迟项 | ENG-006（非 Git Workspace）、ENG-007（算子/插件 IPC）、ENG-009（Alias 持久化）、ENG-010（事件序列化版本化） | §10.2 |

### 1.2 前置

- P6A 的 `continuum-context` 已合入（`ContextPackage` 形状与 `compile` 冻结）。
- 无其他批次前置。

### 1.3 不做

- 不重写规范（留 P9/P10）。
- 不建 UI 本身；不把 SQLite 直读改成正式服务契约（见第四节交付清单）。

### 1.4 完成判据

```
一个真实 Intent 经「模型调用 → 工具执行 → 产物落库 → 验证」跑通，有端到端实测
§279 的「节点执行前必经 Context Compiler」无绕过路径，有围栏测试
四类 Provider Adapter 至少两类在真实凭据下完成冒烟测试
ENG-002 / ENG-003 有裁定记录，且落成对应实现或具名不关闭理由
```

### 2.3 不做

```
ENG-008 / C4 / OPEN-016 关闭，或给出具名「不关闭」理由与收件人

```

**目标**：收掉「系统如何长期记住与遗忘」这一类未决项。

### 3.1 范围

## 四、产品化的归属（不占批次）

P8/P9/P10 每批的完成判据都包含：

```
本批新增能力有可运行的示例与文档
本批引入的配置/密钥/迁移有升级说明
```

### 4.2 交付清单（不编号，P10 之后执行）

- 部署与安装、打包、升级路径；
- 性能基准；
- §119 对抗套件（prompt injection 等安全测试）；
- P5/P6 遗留清账（`p5-followups.md` / `p6-followups.md`）。

### 4.3 UI 与服务层

- UI 本身由外部团队做；接口文档见 `docs/ui-contract/`（6 份）。
- 服务层/查询 API、结构化错误码、二进制名统一、`task` 与 `intent` 行、`effect` 幂等键、`effect.intent_id`——**列入交付清单**，可与 P9 并行（它们是对外契约，不改规范层）。

## 五、顺序与硬前置

```
P7（第 7 层）→ P8（设计阶段先裁 ENG-002/003）→ P9 → P10
```

- **P8 不得跳过 ENG-002/003 的裁定**：它们决定执行层的增量重算与寻址，事后改代价更高。
- **P9 依赖 P8 的真实证据流**；**P10 依赖 P7 的调度框架**。
- P9 与 P10 **不可交换**：P9 的边界裁定会改变 P10 的记忆语义（例如 Protected Core 是否包含 Compiler 影响记忆的写入边界）。
